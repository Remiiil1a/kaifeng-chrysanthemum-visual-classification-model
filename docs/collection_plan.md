## 二、拍摄纪律

1. **先定位、后拍摄**：到达展区先确认地图定位已锁定（蓝点稳定）。
2. **按类别逐类拍**，一类拍完再换下一类，避免后期归类混乱。
3. 每类开头拍一张**类别标识照**（含展区品种标牌），单独存 `_raw/_sign/{类别}/`，
   不进数据集，仅供核对类别名与品种。
4. **按 6 个拍摄位逐株拍完，再换下一株**——这是植株编号能自动推出的前提。
5. 每完成一类，在下表打勾并记录张数。

## 三、6 个拍摄位

| 序号 | 视角 | 目的 | 构图要求 |
| --- | --- | --- | --- |
| 1 | 正面平视 | 花型轮廓 | 镜头与花心等高，主体占画面 1/2 |
| 2 | 45° 斜俯视 | 花瓣层次 | 最常用角度，能看到花瓣排列 |
| 3 | 正俯视 | 花心与瓣序 | 从上往下拍，呈放射状 |
| 4 | 侧面 90° | 花托与花梗 | 体现花的立体厚度 |
| 5 | 近距特写 | 瓣端形态 | 体现平瓣/匙瓣/管瓣的差异 |
| 6 | 整株环境 | 植株比例 | 带背景，体现株高与叶形 |

同时覆盖三种开放程度：花蕾期、初开期、盛开期（记在同一类别下，不单独设类）。

## 四、三类禁止事项

1. 禁止网络图片、他人拍摄图片、AI 生成图片 —— **总分按 0 计**；
2. 禁止对同一张照片旋转/翻转/调色后当多张用；
3. 禁止截图代替拍照（截图不继承 EXIF，无 GPS）。

## 六、转运与清洗（阶段 2）

1. **数据线或网盘原图**拷贝到 `_raw/{类别名}/`，**不要用微信/QQ 传图**（会剥离
   EXIF，任务书 5.2 节明确"永久抹除且不可恢复"）。
2. 抽查 GPS：每类随机 3 张，右键 → 属性 → 详细信息 → GPS 纬度/经度。
3. 剔除废片：模糊、过曝、主体过小、重复、非菊花主体。
4. 去重：`python code/prepare_dataset.py dedupe --src _raw/01_huangse_pingban`
5. 格式统一：HEIC 转 JPG，长边缩到 2048 以内，质量 90，**转换时必须保留 EXIF**。

## 七、命名与归类（阶段 3）

```powershell
# 1) 重命名为 {类别}_{三位序号}.jpg
python code/prepare_dataset.py rename --src _raw/01_huangse_pingban --category 01_huangse_pingban

# 2) 按植株分组划分到 train/val/test（8:1:1，防泄漏）
python code/prepare_dataset.py split --src _raw/01_huangse_pingban `
    --category 01_huangse_pingban --per-plant 9

# 3) 生成元数据表
python code/build_labels.py

# 4) 结构自查
python code/check_dataset.py --strict
```

`split` 是**复制**不是移动，`_raw/` 原目录保留作备份，提交前再删除。
