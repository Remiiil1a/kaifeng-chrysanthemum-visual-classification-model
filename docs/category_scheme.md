# 类别方案（待现场核对）

对应任务书第四章。当前为任务书 4.2 节示例方案，**必须**在采集前对照展区
品种标牌逐类确认；标牌名称与本表不符时以标牌为准，并同步修改目录与 README。

## 一、命名规则

- 文件夹名：`{两位序号}_{类别名拼音}`，**全小写、无空格、无中文**
- 图片名：`{类别文件夹名}_{三位序号}.jpg`，序号从 001 连续编号不跳号
- 两位序号的作用：YOLO 按文件夹名字母序给类别编号，加序号后字母序 = 序号序，
  索引稳定；否则中途插入一类会让所有编号后移，预测结果全部错位。

## 三、选择原则与禁区

**要选**：形态差异肉眼可辨、展区内数量充足、能拍到 3—5 株不同植株的类别。

**不要选**：

- 同一品种的不同颜色（如"黄牡丹"与"白牡丹"——品种相同，属花色差异，可接受但
  需保证形态差异同时存在）；
- 同一品种的"初开"与"盛开"（这是生长阶段差异，不是品种差异，会让模型学到
  与分类目标无关的特征）；
- 展区内只有一两株、无法凑够 30 张的稀有品种。

## 四、开封常见传统名菊（选题参考）

绿牡丹、墨荷、帅旗、黄袍加身、绿云、凤凰振羽、西湖柳月等。

**品种名以展区标牌为准，不得凭印象编造。**

## 五、现场核对后需要同步修改的位置

若某类需要替换，改动点清单（漏一处就会类别错位）：

1. `train/`、`val/`、`test/` 三个目录下的**同名文件夹**（三处必须完全一致）；
2. 本文件第二节表格；
3. `README.md` 第二部分类别说明表；
4. 已有图片的文件名前缀，以及 `labels.csv` 的 `category` 列。
